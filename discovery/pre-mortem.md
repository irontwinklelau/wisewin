## 🐯 上线阻断级 Tigers（不解决不能上线）

### Tiger #1：无限改 bug 循环——没有"上线"的定义

| 维度 | 描述 |
|------|------|
| **失败场景** | 第一课做完了→发现武器库 UI 不好看→改→发现段位动画不流畅→改→发现打卡日期格式不统一→改…两周过去了还在改，从来没有真正"上线使用"过 |
| **可能性** | 🔴 极高。这是你的历史模式——product_principles.md 里写了"MVP 优先"但没定义什么是 MVP 完成标准 |
| **影响** | 🔴 致命。产品从未真正投入使用，30天连续使用指标无从谈起 |
| **根本原因** | PRD 只有功能列表，没有"可上线的最小定义"。开发者和用户是同一个人，永远能挑出毛病 |

**缓解措施**：

```
「可上线」的硬定义（不可妥协）：
  
  用户能在浏览器打开 → 看到今天的状态（段位+连续天数+武器库数量）
    → 点击「今日训练」
      → 看到第一课（受害者叙事觉察 Day 1）
        → 阅读框架讲解
        → 看到菲森面试案例拆解
        → 完成当日练习（至少 1 道题）
        → 点击「打卡」
        → 看到打卡成功的视觉反馈
        → 武器库里多了一张卡片
        → 连续天数 +1

  以上完整流程跑通 + 没有阻断性 bug = 上线。
  
  不在此流程内的功能（错题本、段位动画优化、武器库搜索…）= 上线后再说。
```

### Tiger #2：本地 localhost 无法形成使用习惯

| 维度 | 描述 |
|------|------|
| **失败场景** | 项目跑在 `localhost:8080`，每次要用得先打开终端→启动服务→打开浏览器。某天忘了启动，某天电脑关了，某天换了台电脑没法用。摩擦成本累积→"算了今天不练了"→弃坑 |
| **可能性** | 🟡 中高。用户自己说的"不舍得花钱挂云服务器" |
| **影响** | 🔴 致命。30 天连续使用的敌人不是意志力，是摩擦 |

**缓解措施**：

方案 A（零成本）：
- 写一个批处理脚本放桌面，双击启动服务+自动打开浏览器
- 开机自启动服务（Windows 计划任务或 startup 文件夹）
- 摩擦降到最低：开机就有，点一下进训练

方案 B（低成本）：
- 部署到 Cloudflare Pages（前端）+ Cloudflare Workers（后端逻辑）+ D1（SQLite 兼容数据库）
- 免费额度足够个人使用
- 随时浏览器打开即可，无需开自己电脑

方案 C（极低成本）：
- 部署到 Vercel（前端）+ Railway/Render（后端）
- 有免费层，每月 $0

**建议**：MVP 先用方案 A 验证核心体验。如果连续用了 7 天确认产品方向对了，再花 1-2 小时迁移到方案 B（永久在线）。不要一开始就纠结部署。

### Tiger #3：第一天训练内容不够好→第二天就不来了

| 维度 | 描述 |
|------|------|
| **失败场景** | 第一天打开，框架讲解像教科书（"受害者叙事是指…"），案例拆解就是把审计报告原文贴上去，练习是一道敷衍的选择题。用户觉得"这不就是 AI 生成的内容吗，跟 Gemini 聊天框有什么区别"→关掉→再也不来 |
| **可能性** | 🟡 中。第一期内容依赖 Claude API 生成，质量不稳定 |
| **影响** | 🔴 致命。第一天就决定了用户会不会回来 |

**缓解措施**：
- 第一课（受害者叙事觉察 Day 1）**不依赖 AI 生成**，人工写好内容
- 基于菲森审计报告中最扎心的三个段落，每段配一个"你当时怎么想的"vs"策略选择者会怎么想"的对比
- 练习必须是**开放式的重写题**而非选择题——逼你动脑，不是点一下
- 上线前 Songmin 自己以用户身份完整走一遍，觉得"有意思"才算过

## 🐯 持续监控级 Tigers

### Tiger #6：LLM API 成本不可控

| 维度 | 描述 |
|------|------|
| **失败场景** | 每次生成训练内容消耗大量 token，月底账单超预期，用户心疼钱→减少使用→荒废 |
| **可能性** | 🟢 低（单用户场景，每天一次调用） |
| **影响** | 🟡 中 |

**监控方式**：
- 每次训练生成记录 token 消耗
- 预估：每天 1 次训练 × 每次约 2000-4000 token（生成+评估） ≈ 约 $0.03-0.06/天（Claude Haiku）≈ $1-2/月
- 触发条件：如果单次超过 10000 token，检查是否有异常

## 📄 Paper Tigers（看似可怕，其实可控）

### Paper Tiger #1："这跟用 Gemini 聊天框有什么区别？"

| 为什么是纸老虎 | 什么情况下会变成真老虎 |
|---------------|---------------------|
| 区别不在技术，在**结构**。Gemini 不会记住你的段位、不知道你昨天学了什么、没有课程大纲、没有打卡。用户自己要的东西就是一个结构化的训练系统，不是聊天 | 如果训练内容质量跟 AI 聊天一样浅（泛泛而谈、没有深度拆解、没有你自己的案例），那就真的没区别了。这就是为什么第一课必须人工写好 |

### Paper Tiger #2："一个人用的产品没有规模，不值得做"

| 为什么是纸老虎 | 什么情况下会变成真老虎 |
|---------------|---------------------|
| 这个产品的目的是**让你自己变强**，不是"做一个 SaaS 产品去卖"。只要能让你坚持 30 天并升级到 LV.1，它就值了。规模和商业价值不是当前阶段的评价标准 | 无。产品定位已明确：个人工具 |

## 🐘 房间里的大象（不得不说但不太想说的风险）

### Elephant #1：你自己是最大的风险

这是最不舒服但最需要说的一条。

你说"只要不出 bug，我就天天用"——但前面你也说了"每天被复利思维裹挟，觉得做事情没有办法规律，也没办法执行"。

这两个陈述之间存在张力。不是怀疑你的决心，而是说：**产品设计需要假设用户（你自己）会犯懒**。

具体来说：
- 第一天没打开 → 第二天打开时，不是显示"你断了一天"（惩罚感），而是"没关系，回来就好，今天的内容很简单"（降低回归门槛）
- 连续 3 天没打开 → 自动降为"复习模式"，不出新内容，只复习之前学过的（降低追赶压力）
- 永远不要用"你已经 X 天没来了"这样的提醒——这种提醒只会让你更不想打开

**这是产品设计的重要原则：不要跟用户的意志力较劲，帮他把回归门槛降到零。**

---

### Elephant #2：你已经在为 AI 工具付费了，再加一个 Claude API 调用会不会心疼？

| 维度 | 描述 |
|------|------|
| **现实** | Claude Pro 已经 $20/月。如果这个产品每天还要额外调用 API，会增加心理负担 |
| **缓解** | 使用 Claude Haiku（便宜）生成内容；每天消耗约 $0.03-0.06，一个月不到 $2。但关键不是金额，是**你心里觉得"值不值"** |
| **验证方式** | 先用 7 天走通 MVP，如果你觉得训练内容有价值，$2/月完全不是问题。如果觉得没价值，免费你也不会用 |

---

### Elephant #3：这个产品真的需要是"一个 App"吗？

| 维度 | 描述 |
|------|------|
| **诚实问题** | 本质上，这就是"结构化对话 + 状态持久化 + UI 包装"。有没有可能用更轻的方式实现？比如……Claude Code 本身？ |
| **为什么最终还是应该做 App** | ①你明确说了不想再回到 Gemini 聊天框——你需要的是一个"训练工具"的身份感，不是"聊天"；②打卡、段位、武器库需要可视化界面，聊天框做不到；③启动一个 App 的心理暗示是"现在开始训练了"，和打开聊天框是完全不同的心智模式 |
| **底线** | MVP 必须能证明"App 形态比聊天框有不可替代的价值"。如果做不到这一点，那确实不如不做 |

## Go/No-Go Checklist

- [ ] **「可上线」硬定义已确认**（Tiger #1）——完整流程跑通 + 无阻断 bug = 上线
- [ ] **部署方案已选择**（Tiger #2）——MVP 用方案 A（本地启动脚本），验证后迁方案 B
- [ ] **第一课内容人工写好并通过审核**（Tiger #3）——Songmin 以用户身份完整走一遍，觉得"有意思"
- [ ] **至少备好 7 天训练内容**（Tiger #5）——上线前库存 ≥ 7 天
- [ ] **回归门槛设计已实现**（Elephant #1）——断签不惩罚，复习模式可降级
- [ ] **LLM API 成本预估已确认**（Tiger #6）——上线前跑一次实际调用，确认 token 消耗在预期内

---

> **Pre-Mortem 结论**：没有不可逾越的阻断风险。三个阻断级 Tiger 都有明确的低成本缓解方案。最大的变量不在技术上，在**产品第一天给人的感觉**——第一课的内容质量和仪式感决定了生死。
